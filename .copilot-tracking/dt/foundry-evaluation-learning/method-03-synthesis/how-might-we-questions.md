# How might we questions

These questions carry the synthesis into later design without selecting the module sequence, hosting implementation, or monitoring mechanism.

| ID | Question | Insight | Constraint |
|---|---|---|---|
| HMW-001 | How might we help learners explain evaluation value and limits using evidence a customer can understand? | INS-001 | Basic Foundry knowledge, no previous evaluation practice required |
| HMW-002 | How might we help learners turn an expectation into repeatable checks without implying identical answers or arbitrary quality targets? | INS-002 | Use supplied facts, read-only scope, and fictional policy rather than airline expertise |
| HMW-003 | How might we make individual failures and their causes visible enough to support an informed change or release decision? | INS-002 | A weighted average must not conceal a designated critical failure |
| HMW-004 | How might we help learners investigate quality failures in live lab-agent activity and carry that process into customer operations? | INS-003 | Production evaluation is hands-on core work with synthetic activity |
| HMW-005 | How might we preserve reusable evaluation assets after handover without making CI-platform skills a core prerequisite? | INS-003 | Runnable GitHub Actions evaluation is optional extra credit |
| HMW-006 | How might we preserve primary evaluation learning when a deployment cannot run Optimizer or red-team activities? | Delivery boundary | Report actual limitations without treating skipped work as successful execution |
| HMW-007 | How might we help delivery engineers adopt evaluation early and repeatedly assess changes against non-functional quality requirements while building? | Requester requirement: evaluate while building | Keep requirement-to-evidence links explicit; local execution must not depend on optional CI/CD |
| HMW-008 | How might we help partner engineers, consultants, and architects use Microsoft Foundry evaluation features and explain their value in customer solutions? | Requester objective: Microsoft Foundry capability and awareness | Core work must not require a third-party evaluation platform; feature claims must reflect actual use and verified limits |

Status: draft synthesis questions for review, not validated solution concepts. See `problem-definition.md` for the five-dimension assessment.
